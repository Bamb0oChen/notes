## 一、知识定位

本章解决的是「怎么让硬件活起来」的问题。硬件组装完成后只是一堆金属和硅片，操作系统是赋予它们生命的灵魂。系统搭建的本质，是在物理硬件之上构建一个「软件可运行的环境」，包括：引导程序、内核、驱动、用户空间、服务管理、存储挂载、容器运行时。

本章的知识递进关系：**物理硬件 → 固件(BIOS/UEFI) → 引导程序(Bootloader) → 操作系统内核 → 用户空间 → 应用运行时**

## 三、逐层展开

### 3.1 固件与引导层

#### 3.1.1 BIOS vs UEFI

这是计算机加电后最先运行的软件，负责初始化硬件并启动操作系统。理解这两者的区别，是理解「为什么有些系统装不上」的基础。

| 维度 | BIOS (Legacy) | UEFI |
|------|---------------|------|
| **全称** | Basic Input/Output System | Unified Extensible Firmware Interface |
| **位宽** | 16位实模式 | 32/64位保护模式 |
| **磁盘支持** | MBR分区表，最大2TB | GPT分区表，最大18EB |
| **启动速度** | 慢（逐设备轮询） | 快（并行扫描） |
| **启动设备数** | 4个主分区限制 | 128+个分区 |
| **安全启动** | 不支持 | 支持（Secure Boot） |
| **启动引导** | 从第一个扇区读取boot code | 直接从EFI分区读取.efi文件 |
| **2026年主流** | 逐步淘汰 | 全面普及 |

**MBR vs GPT 的本质区别**：
- **MBR**：磁盘开头保留 512 字节（主引导记录），其中 64 字节用于分区表（每 16 字节描述一个分区），所以只能有 4 个主分区。解决方法是把其中一个主分区设为「扩展分区」，在里面再切「逻辑分区」，但这种方式复杂且有限制。
- **GPT**：磁盘开头保留一个保护性 MBR（防止老工具误识别），真正的分区表在磁盘后部备份。用 GUID（全局唯一标识符）识别分区，理论上支持无限分区数，实际受操作系统限制。

**你的主板（华擎 B75 Pro3）同时支持两种模式**。在 BIOS 中可以切换 CSM 兼容性支持模块：开启 CSM = 支持 Legacy BIOS 启动（MBR）；关闭 CSM = 纯 UEFI 模式（GPT）。2026 年建议用 UEFI+GPT，因为：更快、支持 >2TB 系统盘、支持 Secure Boot（安全启动）。

#### 3.1.2 启动顺序与启动介质

计算机加电后的启动设备搜索顺序：
1. 按预设顺序轮询存储设备（硬盘、U盘、光驱、网络）
2. 找到第一个可启动介质后加载其引导程序
3. 找不到任何启动介质则报错 "No bootable device"

**制作启动 U盘 的两种写入模式**：
- **ISO 写入模式（DD 模式）**：逐扇区复制 ISO 镜像到 U盘，包括 ISO 的引导信息。兼容性最好，所有系统都能启动。
- **分区写入模式**：将 ISO 文件解压到 U盘的一个分区，同时单独安装引导程序。部分老主板兼容性差。

Rufus 写入 Ubuntu ISO 时会询问「建议 DD 模式」，选择 DD 模式成功率最高。

### 3.2 操作系统选型层

#### 3.2.1 服务器发行版 vs 桌面发行版

| 维度 | 服务器发行版 | 桌面发行版 |
|------|-------------|-----------|
| **图形界面** | 默认无 GUI | 带完整的桌面环境 |
| **内存占用** | 约 500MB-1GB | 约 2GB-4GB |
| **预装软件** | 最小化安装，只有核心工具 | 办公、多媒体、浏览器等 |
| **更新策略** | 保守稳定，安全更新为主 | 功能更新频繁 |
| **内核版本** | 较老但久经测试 | 较新但可能有新 bug |
| **典型代表** | Ubuntu Server、Debian、CentOS | Ubuntu Desktop、Fedora |

**为什么服务器要用最小化安装**：
1. 减少攻击面：少一个软件包，少一个潜在漏洞
2. 减少资源竞争：GUI 会抢占 CPU、内存、I/O
3. 便于自动化管理：命令行可被脚本、Ansible 等工具批量控制
4. 故障排查更直接：不受图形界面层遮挡

#### 3.2.2 LTS vs 非 LTS 版本

LTS（Long Term Support）是 Ubuntu 特有的长期支持版本，每 2 年 4 月发布一次（如 20.04、22.04、24.04），每 5 年、10 年、12 年不等。非 LTS（或称中间版本）每 6 个月发布一次，支持 9 个月。

| 版本类型 | 发布频率 | 支持周期 | 适用场景 |
|----------|---------|----------|----------|
| **LTS** | 2 年 | 5 年（标准），可付费延长至 12 年 | 服务器、生产环境 |
| **非 LTS** | 6 个月 | 9 个月 | 桌面尝鲜、开发测试 |

**选择 LTS 的理由**：
- 你的服务器装一次可能跑几年，这期间不想「被迫」升级
- 安全更新和软件仓库支持在 5 年内持续提供
- Docker、Kubernetes 等云原生生态优先兼容 LTS
- 搜索结果中大量教程和脚本假设用的是 LTS

**推荐的 Ubuntu Server LTS 路线**（2026 年视角）：
- 22.04 Jammy：支持到 2027 年 4 月，生态最成熟，教程最多
- 24.04 Noble：支持到 2029 年 4 月，更新但文档相对少
- 你的选择：优先 22.04，等 24.04 生态完善后再考虑迁移

### 3.3 系统安装层

#### 3.3.1 启动盘制作流程

**1. 下载 ISO 镜像**
- 官方源：`https://ubuntu.com/download/server`
- 国内镜像：中科大、清华、阿里云（下载速度快）

**2. 制作启动 U盘（以 Rufus 为例）**

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 插入 U盘（注意：会清空数据） | 建议 8GB 及以上 |
| 2 | 打开 Rufus，自动识别 U盘 | 若识别错误，手动选择 |
| 3 | 点击「选择」，选中下载的 ISO | 自动推荐合适的分区方案 |
| 4 | 分区类型选「GPT」 | UEFI 模式用 GPT，老机 Legacy 用 MBR |
| 5 | 目标系统选「UEFI（非 CSM）」 | 现代主板推荐 |
| 6 | 点击「开始」，弹出提示选「DD 模式」 | DD 模式兼容性最好 |
| 7 | 等待写入完成，弹出 U盘 | 写入完成后可「弹出」安全移除 |

#### 3.3.2 分区方案

分区是给硬盘划定不同用途的区域。一个硬盘被分成多个「卷」，每个卷可以用不同的文件系统格式。

**标准 Linux 服务器的分区布局（以 120G SSD 为例）**：

| 分区 | 大小 | 文件系统 | 挂载点 | 用途 |
|------|------|----------|--------|------|
| **ESP** | 512MB | FAT32 | `/boot/efi` | UEFI 引导分区，存放 .efi 引导文件 |
| **根分区 /** | 剩余全部（约 119.5G） | ext4 | `/` | 系统、应用、配置文件 |
| **swap** | 可选（建议 4-8G） | swap | 不挂载 | 内存溢出时的备换区 |

**为什么需要单独的 ESP（EFI System Partition）**：
- UEFI 固件只能识别 FAT 格式的分区
- ESP 存放操作系统的引导加载程序（如 `grubx64.efi`、`shimx64.efi`）
- 多个操作系统可以共存于 ESP，实现多系统引导
- ESP 大小 512MB 足够容纳多个引导程序

**为什么 swap 对服务器很重要**：
- 内存写满时，系统可以将不活跃的内存页临时写入 swap，释放物理内存
- 没有 swap，内存写满会触发 OOM Killer（内存溢出杀手进程）直接杀死进程
- 服务器 OOM 可能导致 Docker 容器被系统强制终止，体验很差
- 建议 swap 大小 = 内存大小（<=8GB）或内存×0.5（>8GB）

#### 3.3.3 文件系统选择

| 文件系统 | 特点 | 适用场景 |
|----------|------|----------|
| **ext4** | Linux 默认标准，稳定成熟，性能好 | 系统盘 / 和 /boot |
| **XFS** | 大文件性能优，支持在线扩容 | 数据盘存储大文件（视频、备份） |
| **ZFS** | 支持数据校验、快照、压缩、RAID | 高端 NAS、OpenZFS，需要大量内存 |
| **Btrfs** | 支持快照、压缩，功能类似 ZFS | NAS 发行版（如 Synology），稳定性略低于 ZFS |

服务器系统盘（`/` 和 `/boot`）推荐 **ext4**，原因是：最成熟、出问题修复工具最多（fsck）、所有 Linux 发行版都原生支持、性能稳定无惊喜。

#### 3.3.4 最小化安装原则

**在 Ubuntu Server 安装器中，有两个关键选项**：
1. **「安装基础系统」**：仅安装最核心的包（约 500MB）
2. **「安装 OpenSSH Server」**：勾选此项，否则装完没 SSH，每次调试必须插显示器

**最小化安装的包筛选逻辑**：
- 不装 GUI（不选 Ubuntu Desktop）
- 不装额外的服务器软件（LAMP、邮件服务器等，按需后装）
- 不装 Snap 包（Ubuntu 默认会装，但可以稍后卸载）
- 安装后可以查看「已安装的包数量」：`dpkg -l | wc -l`，最小化约 400-500 个包

**为什么最小化是服务器安全的第一道防线**：少装一个包，就少一个潜在漏洞；少一个服务，就少一个可能的攻击入口。不需要的软件服务（如蓝牙、打印）不应该在内核里加载。

### 3.4 系统配置层

#### 3.4.1 网络配置：从 DHCP 到静态 IP

服务器必须有固定的 IP 地址，否则路由器重启或 DHCP 租约到期后，服务器 IP 会变化，所有依赖 IP 的服务都会断。

**Ubuntu 22.04+ 使用 Netplan 配置网络**：

```yaml
# /etc/netplan/00-installer-config.yaml
network:
  version: 2
  ethernets:
    enp3s0:    # 网卡名称，通过 ip a 查看
      dhcp4: no
      addresses:
        - 192.168.50.175/24    # 固定IP/子网掩码
      routes:
        - to: default
          via: 192.168.50.1     # 网关
      nameservers:
        addresses:
          - 223.5.5.5           # 国内推荐 DNS：阿里/114/Google
          - 119.29.29.29
```

应用配置：`sudo netplan apply`。注意：YAML 对缩进敏感，建议用 2 空格，不要用 TAB。

**网卡名称的命名规则（Predictable Network Interface Names，可预测网络接口名）**：
- 传统方式：`eth0`、`eth1`（不可预测，插入顺序改变会漂移）
- 现代方式：`enp3s0` = en（以太网），p3（PCI 总线 3），s0（插槽 0）
- 特点：基于硬件位置命名，重装系统或换网卡插槽才变，可预测
- 查看网卡名：`ip a` 或 `ls /sys/class/net/`

#### 3.4.2 软件源配置

Ubuntu 默认源在海外，国内下载 apt 包可能只有几 KB/s。镜像源是官方软件仓库的副本，用国内镜像源加速下载。

**换源原理**：`/etc/apt/sources.list` 文件中记录了从哪里下载包。把 `archive.ubuntu.com` 替换为 `mirrors.ustc.edu.cn`，所有请求指向中科大镜像。

**换源命令**：

```bash
# 备份原文件
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

# 替换为清华源（或中科大、阿里云）
sudo sed -i 's@//.*archive.ubuntu.com@//mirrors.tuna.tsinghua.edu.cn@g' /etc/apt/sources.list
sudo sed -i 's@//security.ubuntu.com@//mirrors.tuna.tsinghua.edu.cn@g' /etc/apt/sources.list

# 更新软件列表
sudo apt update
```

**国内主流镜像源**：清华 tuna（教育网快）、中科大 USTC（综合稳定）、阿里云（商业宽带快）、华为云。

#### 3.4.3 用户与权限

**root 用户 vs 普通用户 + sudo**：
- root 是超级管理员，拥有系统最高权限
- 直接使用 root 的风险：误操作删除系统文件没有二次确认；任何程序运行都有最高权限（包括恶意脚本）；审计日志无法区分是哪个操作员执行的

**最佳实践**：日常用普通用户，临时提权用 `sudo`。`sudo` 会记录日志（`/var/log/auth.log`），可精确追溯到谁在什么时间执行了什么提权命令。

**SSH 配置强化**：

```bash
# 编辑配置文件 /etc/ssh/sshd_config
PermitRootLogin no              # 禁止 root 登录
PasswordAuthentication no       # 禁止密码登录（前提：已配置好 SSH 密钥）
PubkeyAuthentication yes        # 开启密钥登录
Port 22                         # 可以改其他端口（增加一层隐蔽）

# 重启服务生效
sudo systemctl restart sshd
```

**SSH 密钥认证原理**：
- 客户端生成一对密钥（公钥 + 私钥）
- 公钥放在服务器 `~/.ssh/authorized_keys`
- 登录时，服务器用公钥加密一个随机数发送给客户端，客户端用私钥解密并发回验证
- 安全性：私钥不离客户端，公钥放在服务器（泄露无风险）

#### 3.4.4 时间同步

服务器对时间一致性要求极高（日志时间戳、证书有效期、定时任务）。主板电池 CMOS 时间靠不住，需要通过网络同步。

```bash
# 安装 chrony（替代老旧 ntpd）
sudo apt install chrony

# 启用并启动
sudo systemctl enable chrony
sudo systemctl start chrony

# 查看同步状态
chronyc sources -v
```

**chrony 的优势**：适应网络延迟波动更好、初始同步更快、支持离线期间时钟补偿（放了几周再开机也能快速校准）。

### 3.5 存储与运行环境层

#### 3.5.1 数据盘挂载

**设备名的漂移问题**：Linux 的设备名（`/dev/sda`、`/dev/sdb`）是内核检测顺序分配的，不一定固定。插拔硬盘、换 SATA 口、加新盘，设备名可能变化。直接用设备名挂载，重启后可能挂错盘。

**UUID 解决漂移问题**：UUID 是在格式化时随机生成的 128 位标识符，储存在文件系统超级块中，不依赖于设备名、插槽顺序。

```bash
# 查看所有块设备的 UUID
sudo blkid

# 输出示例
/dev/sda1: UUID="1234-5678" TYPE="vfat" PARTUUID="..."
/dev/sdb1: UUID="abcd-efgh" TYPE="ext4" ...
```

**/etc/fstab 的正确写法**：

```
# <设备标识>          <挂载点>     <类型>   <选项>          <dump> <pass>
UUID=abcd-efgh       /mnt/data    ext4     defaults,nofail  0      2
```

**挂载选项解释**：
- `defaults`：默认选项组合（rw、suid、dev、exec、auto、nouser、async）
- `nofail`：挂载失败时不阻塞系统启动（数据盘挂了系统还能进）
- `noatime`：不更新文件的访问时间戳，减少 SSD 写入量，服务器常用优化

**验证 fstab 正确性**：

```bash
sudo mount -a    # 无报错说明配置正确
df -h            # 确认挂载点已出现
```

#### 3.5.2 Docker 运行时

Docker 不是虚拟机，而是「容器」。容器的本质是：
- 一个被隔离的 Linux 进程（或进程组）
- 共享宿主机的内核，不模拟完整操作系统
- 通过 namespace 隔离资源（PID、网络、文件系统、用户等）
- 通过 cgroup 限制资源使用（CPU、内存、磁盘 I/O）

**安装 Docker**：

```bash
# 1. 安装依赖
sudo apt install -y ca-certificates curl

# 2. 添加 Docker 官方 GPG 密钥
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

# 3. 添加 Docker 仓库
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# 4. 安装 Docker 引擎
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 5. 将当前用户加入 docker 组（免 sudo 运行 docker）
sudo usermod -aG docker $USER
newgrp docker

# 6. 验证安装
docker run hello-world
```

**用户组 `docker` 的安全含义**：加入 `docker` 组的用户，可以通过 Docker 命令直接控制宿主机内核（因为容器共享内核）。相当于拥有了几乎等同于 root 的权限。所以只给可信用户加 `docker` 组。

#### 3.5.3 系统监控基础

**systemd**：Linux 的 init 系统（PID 1），管理所有系统服务和进程。

```bash
# 查看服务状态
systemctl status docker

# 查看最近日志（journald 存储）
journalctl -u docker -n 50 --no-pager
```

**资源查看命令速查**：

| 命令 | 用途 | 常用选项 |
|------|------|----------|
| `free -h` | 内存使用 | `-h` 人类可读 |
| `df -h` | 磁盘使用 | `-i` 查看 inode 使用 |
| `top` / `htop` | 实时进程 | `htop` 更友好 |
| `docker stats` | 容器实时资源 | 类似 top 但看容器 |
| `uptime` | 系统运行时长 + 负载 | 负载 1/5/15 分钟 |
| `dmesg -T` | 内核日志（包含硬件错误） | `-T` 显示时间戳 |

**负载（load average）的含义**：
- 1/5/15 分钟的平均活跃进程数（正在运行 + 等待运行）
- 值超过 CPU 核心数说明有进程在排队
- 你的 E3-1230 v2 是 4 核 8 线程，正常负载应 <4.0
- 服务器持续负载 >4.0 说明 CPU 不够用

## 四、本章核心概念速查表

| 概念 | 一句话解释 | 实际应用 |
|------|-----------|----------|
| **UEFI vs BIOS** | 两种固件标准 | 新机用 UEFI+GPT，老机 Legacy |
| **ESP 分区** | EFI 系统分区，FAT32，存放引导文件 | 必须挂载于 `/boot/efi` |
| **ext4** | Linux 默认文件系统 | 系统盘推荐用 ext4 |
| **LTS** | Ubuntu 长期支持版本 | 服务器选 22.04 LTS 或 24.04 LTS |
| **Netplan** | Ubuntu 的网络配置工具 | YAML 配置静态 IP |
| **软件源** | apt 下载软件包的仓库 | 换国内源加速 |
| **UUID** | 文件系统的唯一标识 | fstab 用 UUID 避免设备名漂移 |
| **Docker** | 容器运行时 | 推荐安装官方 Docker，非 Ubuntu 自带 |
| **`sudo`** | 临时提权执行单条命令 | 比直接 root 安全 |
| **SSH 密钥** | 免密码登录 | 比密码更安全，禁止密码登录 |
| **swap** | 内存溢出的备换区 | 建议 4-8GB |
| **load average** | 系统负载 | 超过 CPU 核心数说明排队 |
