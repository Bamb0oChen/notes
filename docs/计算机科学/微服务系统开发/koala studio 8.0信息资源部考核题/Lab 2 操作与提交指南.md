这份指南配合 [Lab 2：开发者的基本素养](./2.%20开发者的基本素养.md) 使用。**提交截止：2026 年 11 月 15 日 23:59（北京时间）。**

这一阶段最后验收两件事：用自己的考拉工作室账号创建 GitLab 分支；提交一份能让别人跟着你重走学习过程的报告。建议先把分支建好，再边做题边记证据，避免最后回头找截图。

## 一 先把自己的分支建好

1. 打开工作室 GitLab，选择考拉工作室 SSO，用自己的账号登录。登录后看右上角的用户信息，确认当前账号是自己的。
2. 进入所在的试用期组，打开负责人指定的仓库。注意区分「组」和「仓库」：组下面可以有多个项目，分支建在具体仓库里。
3. 在仓库的 **代码 → 分支（Code → Branches）** 页面创建新分支。起点按组内通知选择；未另外指定时，从仓库默认分支创建。分支名按组内约定填写；没有约定时，可以用 `lab2/你的GitLab用户名`。
4. 创建后切换到个人分支，确认分支名和仓库路径。把仓库链接、分支名和 GitLab 用户名记到报告开头。最后提交文件前，再看一次编辑器选中的分支。

如果页面上没有「新建分支」，或者提示无权限，先确认账号、所在组、仓库和起点分支，记下错误原文再找管理员。不要借用他人的账号。用网页编辑器提交即可；如果你在本地使用 Git，可以用 `git status -sb` 确认当前分支，提交后到 GitLab 检查远端是否已经看到这次提交。

## 二 用开发者工具走完调试题

用 Chrome 或 Edge 打开题目页面，按 **F12**（也可以右键「检查」）。先认识三个面板：

| 面板 | 这道题里用来做什么 |
| --- | --- |
| Application（应用）→ Storage → Cookies | 检查当前站点存了什么 Cookie |
| Console（控制台） | 对自己复制出的练习文本做解码，检查每一步得到的内容 |
| Network（网络） | 看浏览器实际请求了哪个地址、返回什么状态和内容 |

### 1 找到按钮留下的线索

先在 **Application → Cookies** 里选中题目所在站点，观察现有条目；再点击题目里的按钮，回到同一位置查看变化。必要时刷新 Cookie 列表。记录变化的是哪个条目、你怎样确认它和按钮有关。

这一步是页面脚本写入 Cookie，所以点击按钮后未必会出现一条新网络请求，也不应期待找到服务器返回的 `Set-Cookie`。如果没找到线索，先核对站点和当前打开的标签页，不要把登录系统的会话 Cookie 当成题目材料。

### 2 解码并检查地址

题面给了 Base64 的提示。先用无关的小例子练习：在 Console 输入 `atob("aGVsbG8=")`，应得到 `hello`。再用同样的方法处理你找到的练习值。Base64 是**编码**；解码后看见可读文字，并不表示你已经完成第二段密文的解密。

接下来，试着把解码结果当作地址读一遍：哪里是协议，哪里是站点，哪里是路径？如果打不开，先记录原样访问时发生了什么，再根据你观察到的结构判断哪些内容属于地址、哪些是额外线索。每次只改一处，便于说明是什么改变了结果。

### 3 用 Network 验证你的判断

在要打开地址的标签页先打开 **Network**，再访问修正后的地址。可以筛选 **Doc**，选中主文档请求：

- 在 **Headers** 看请求地址和状态码。
- 在 **Response** 看返回的内容是否与预期一致。
- 如果原始地址在发出请求之前就被浏览器拒绝，报告应写「未发出请求」，不要给它编一个 HTTP 状态码。需要跨页面对比时，可以打开 **Preserve log** 保留记录。

报告里的关键不是「最后打开了」，而是让读者知道：你改了什么，以及你凭什么判断改对了。

### 4 处理第二段密文并复查

从第二个页面拿到密文后，结合题面提供的信息与前一步留下的线索，说明你怎样判断处理方法、使用了什么输入、得到什么结果。可以用 Console，也可以写一小段自己能解释的代码。报告留出可以复做的步骤，别只贴最终明文。

做完后从题目页面再走一遍，确认线索、地址和解密过程都能复现。如果第一次判断错了，记录当时的想法和改变判断的证据；如果没有实际遇到误判，如实写你是怎样排除其他可能的。

## 三 把过程写成一份报告

建议用下面的结构。截图放在对应步骤下面，配一句话告诉读者它证明了什么。文字能够解释清楚的步骤不需要硬凑截图。

```text
姓名：
GitLab 用户名：
仓库地址：
个人分支：

1. 一次网页访问是怎样发生的
   选一个实际访问，说明浏览器、网络和服务器分别做了什么。

2. 环境与 Git 准备
   写明用到的工具、如何登录并创建个人分支、
   如何确认报告提交到了正确的分支。

3. 调试过程
   按「操作 → 观察到的证据 → 我的判断 → 验证结果」记录。
   覆盖 Cookie、Base64 解码、地址修正、网络请求和第二段密文。

4. 复盘
   写出一次真实的误判或一个你主动排除的可能，
   以及从头重做时怎样确认结果一致。
```

第一章和第二章可以用同一次网页访问串起来。例如，第一章说明地址如何变成浏览器发出的请求；第二章就用 Network 里的实际记录说明你的请求到了哪里、拿到了什么。没有在工具里直接看到的步骤，可以写成原理解释，不必说成是截图里已经验证的事实。

## 四 提交前检查

- [ ] 用的是自己的 SSO 账号，分支建在试用期组指定的仓库。
- [ ] 报告包含姓名、GitLab 用户名、仓库地址和分支名。
- [ ] 每个关键步骤有操作、证据和判断，另一个人能照着复做。
- [ ] 截图已遮住真实密码、令牌、会话 Cookie 等信息；调试线索与真实凭据已区分。
- [ ] 在 GitLab 网页打开个人分支里的报告，确认正文和图片都能看到。

报告可按提交通知放在个人分支的 `lab2/report.md`，图片放在 `lab2/images/`，例如用 `![请求记录](./images/request.png)` 引用。如果组内通知指定了其他路径或回填入口，以通知为准。
