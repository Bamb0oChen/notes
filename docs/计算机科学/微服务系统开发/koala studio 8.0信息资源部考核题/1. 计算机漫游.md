假设我们在浏览器里打开一个页面，按下按钮，几秒后屏幕上出现结果。我们一般会说「前端发了个请求，后端返回了数据」：但是你想没想过，手指按下去的信号怎么进电脑？程序在哪里运行？数据又是怎么跑到另一台机器上的？

这一章请先学完**工作室知识图谱的 Level 1**。下面这次「计算机漫游」不是另一份互不相干的材料：学图谱时碰到硬件、操作系统和网络，就回到同一次点击里想一想它们分别做了什么；读完本章，再检查自己能否把图谱中的知识接成一条完整的请求链路。具体学习范围以工作室发布的 Level 1 为准。

## 1.1 先看看我们手上的机器

从键盘输入开始，按键信号经设备接口进入计算机，操作系统得到输入事件，浏览器进程才知道你做了什么。浏览器的代码由 CPU 执行，运行时的数据主要待在内存里；程序文件和需要持久保存的内容一般放在存储设备中。网卡负责把要发出去的数据交给物理网络。

所以，这几个部件在一次请求里的作用并不一样：

| 部件 | 在这趟旅程中做什么 | 想一想 |
| --- | --- | --- |
| CPU | 执行浏览器和服务端程序的指令 | 为什么程序不能只放在硬盘里就自己跑？ |
| 内存 | 放运行中的代码和数据 | 关掉程序后，哪些东西还会留下？ |
| 存储设备 | 保存程序和需要持久化的数据 | 每次点击按钮都一定会访问磁盘吗？ |
| 网卡 | 收发网络数据 | 发到网卡之前，数据是谁组织好的？ |
| 键盘与显示设备 | 让人输入、看见结果 | 应用程序怎样知道按键和画面变化？ |

如果想把「程序怎么被造出来」也补上，可以看我记的 [CSAPP 计算机漫游](../../CMU%20CSAPP/Part%200.5%20Compute%20Roming.md)：从源代码到可执行文件，再到程序运行。

## 1.2 操作系统

浏览器不是直接独占 CPU、内存和网卡。操作系统负责管理进程、分配内存、处理文件与设备，并提供网络通信的接口。浏览器要发请求，会通过系统提供的接口使用网络；服务端进程收到数据后，仍要经过操作系统读写文件、访问数据库或发送响应。

1. **程序与进程**：程序是存放在磁盘上的代码，进程是它运行起来后的状态。
2. **用户态与内核态**：应用不能随意操作所有硬件资源，需要通过系统调用请求内核帮忙。
3. **内存与文件**：内存让程序工作，文件让数据在程序退出后仍然存在；虚拟内存还给不同进程提供各自的地址空间。

我在 [ZJU HPC101 的软硬件基础和运维](../../ZJU%20HPC101/Lecture%201%20软硬件基础和运维.md)里画过 Hardware → Linux Kernel → Shell / Application 的层次；[虚拟内存与分页技术](../../Cursh%20Course%20CS/虚拟内存与分页技术.md)则可以帮你理解进程为什么看到的是自己的地址空间。读的时候别把这两篇当成两门独立的课：一次浏览器请求就会同时经过它们。

## 1.3 网络把两台机器接起来

浏览器知道域名，还得找到目标地址。DNS 帮忙解析域名；建立连接后，数据通过网络协议送到服务端。常见的 HTTPS 请求还会经过 TLS，HTTP 则告诉服务端请求什么、带了什么数据。服务器返回响应，再沿网络回到浏览器。

你可以沿着这条线追：

```text
域名 → DNS → 目标地址 → 建立连接 → HTTP 请求
                                 ↓
浏览器显示 ← HTTP 响应 ← 服务端进程处理
```

其中，「目标地址」不是「目标程序」：IP 帮我们找机器，端口帮助找到机器上的服务，服务端进程最终处理请求。数据在链路上传送时还会经过网卡、交换机和路由设备。网络这一段，可以回看我写的 [计算机网络](../../Cursh%20Course%20CS/计算机网络.md) 和 [HPC101 的抓包实践](../../ZJU%20HPC101/Lecture%201%20软硬件基础和运维.md#wireshark)
## 1.4 把三层重新接起来

现在再看一次「点击按钮」：

```text
人按键 / 点击
  → 设备产生输入 → 操作系统交给浏览器进程
  → CPU 执行浏览器代码，在内存中准备请求
  → 操作系统的网络接口 → 网卡 → 网络 → 服务端网卡
  → 服务端操作系统 → 服务端进程 → 必要时访问持久化数据
  → 响应沿网络返回 → 浏览器处理 → 画面变化
```

当然，这个流程是帮助理解的简图，实际系统可能有缓存、代理或更多服务。

如果请求失败，三层都可能出问题：网卡或连接断了；操作系统里的服务进程没有运行或端口没有监听；或者请求其实已经到达程序，但程序处理时出了问题。
