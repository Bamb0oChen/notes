假设你打开一个纳新页面，填上姓名，点击「提交」。屏幕上只是多了一句「提交成功」，但计算机背后已经忙活了一圈。

浏览器把输入组装成请求，网络把请求送到服务器，程序检查数据并写入数据库，最后服务器把结果送回来。我们先别急着上框架，从这条路看一遍，后面的开发就不至于像在黑盒里摸索。

这条路的两端，我之前其实分别记过：[CSAPP 计算机漫游](../../CMU%20CSAPP/Part%200.5%20Compute%20Roming.md)从 `hello.c` 怎样变成可执行程序讲起；[计算机网络](../../Cursh%20Course%20CS/计算机网络.md)则把 MAC、IP、TCP 和 HTTP 一层层放进数据传输里。现在我们把两篇笔记接起来，拿一次报名请求看看它们怎样在同一个系统里相遇。

```text
键盘输入 → 浏览器页面 → HTTP 请求 → 服务端程序 → 数据库
                                             ↓
页面反馈 ← 浏览器解析 ← HTTP 响应 ← 业务处理结果
```

## 1.1 页面里有什么

你看到的表单一般由 HTML 描述结构，由 CSS 决定样式，由 JavaScript 处理交互。点击按钮后，JavaScript 可以先检查「姓名是否为空」，再把数据发给服务器。

不过请注意：**浏览器里的检查只是为了让用户少等一次报错，不能代替服务端检查。** 用户可以绕过页面直接调用接口。假如服务端照单全收，一个空姓名照样可能进数据库。

### 小练习 A：找到请求

打开自己能操作的网页，在浏览器开发者工具的 Network 面板里观察一次请求，记录 URL、方法、状态码、请求体和响应体，再对照页面发生的变化。不要提交别人的令牌、Cookie 或个人信息。可以等第三章的小项目做好后回来观察。

## 1.2 请求是怎么找到服务器的

浏览器知道域名，仍然需要知道向哪里建立连接。DNS 把域名解析成可用于通信的地址；IP 负责寻址；传输层把数据送到目标进程。对于常见的 HTTPS 页面，还会通过 TLS 建立加密连接。实际网络里可能还有代理和网关，但我们先抓住主线。

一个 HTTP 请求至少要看四件事：

| 部分 | 例子 | 你需要问什么 |
| --- | --- | --- |
| 方法 | `POST` | 这次是读取，还是提交、修改数据？ |
| 路径 | `/api/applications` | 这条请求要找哪个功能？ |
| 请求头 | `Content-Type: application/json` | 数据是什么格式？有没有身份信息？ |
| 请求体 | `{"name":"小考拉"}` | 用户到底交了什么？ |

服务端返回状态码和响应体。成功创建通常可以返回 `201`，请求内容不合法可以返回 `400`，找不到资源可以返回 `404`。状态码让浏览器、测试脚本和其他服务知道发生了什么。

### 小练习 B：解释一次失败

如果点击提交后页面报错，按照「浏览器有没有发出请求 → 请求到没到服务端 → 服务端有没有写库 → 响应有没有回来」逐层排查。不要看到页面没有变化就断言「后端挂了」。把排查顺序写成五六句话即可。

## 1.3 服务器收到请求之后

以报名为例，服务端至少要考虑：

1. 这份数据格式对不对？必填项有没有缺失？
2. 这个人有没有权限执行当前操作？
3. 同一份报名是否已经存在？
4. 写入数据库失败时，应该怎样告诉调用方？

**认证**回答「你是谁」，**授权**回答「你能做什么」，**校验**回答「这份输入是否符合规则」。一个人已经登录，不代表他有权修改别人的报名；一份字段齐全的数据，也不代表提交者有这个权限。

## 1.4 数据库为什么不能只是一个文件夹

如果每来一份报名就追加一行文本，看起来也能存数据，但修改、查询、去重和多人同时提交会越来越难。数据库帮我们组织记录、建立约束、查询数据，并在需要时以事务维护一组操作的一致性。

最简单的报名表可以有 `Id`、`Name`、`CreatedAt` 等字段。不要靠姓名当唯一标识，因为重名很正常。假设两个人几乎同时提交同一个编号，代码里先查「不存在」再分别写入，两次查询都可能看到「不存在」。真正要求唯一时，还需要数据库约束兜底。

## 1.5 一台电脑和一个系统

本地开发时，浏览器、服务端和数据库可能都跑在同一台电脑上。上线后，它们可以在不同机器或容器里。于是会出现一类很常见的问题：本地 `localhost` 能通，换个环境就连不上。

`localhost` 指的是**当前这台机器自己**。浏览器里的 `localhost`、容器里的 `localhost`、服务器上的 `localhost`，未必是同一个地方。碰到连接失败时，先画出「谁在连接谁」，再检查地址、端口和网络路径。
